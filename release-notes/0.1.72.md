PowerDNS, Rspamd, ModSecurity's rules (OWASP CRS), phpMyAdmin and Adminer move from the old versions in Ubuntu 24.04 to current releases from their makers. New servers get them at setup. Existing servers are not changed on their own: each one is upgraded from Software when you choose, with checks and a 7-day undo.

- **PowerDNS 5.1** (was 4.8.3, which PowerDNS stopped supporting in June 2026 and which gets no more security fixes; the October 2026 advisory, for example, was fixed only in 4.9.18, 5.0.8 and 5.1.5):
  - **New servers:** the DNS server setup installs PowerDNS 5.1 from PowerDNS's own package archive (`repo.powerdns.com`, `noble-auth-51`), with its signing key checked and `pdns-*` packages pinned to that archive. If the archive cannot be reached during setup, Ubuntu's 4.8.3 is installed as before and the upgrade below is offered.
  - **Existing servers are not changed on their own.** Software → Other components now lists PowerDNS with its version; **Upgrade version** moves it to 5.1. Server DNS settings shows the same offer next to the version.
  - **How the upgrade works:** the archive is added first (if it cannot be read, nothing else changes). The installed 4.8 packages are downloaded and kept, and every zone, record set and DNSSEC key is saved. PowerDNS then stops and its database is copied, because PowerDNS 5 moves the database to a new format the moment it starts and 4.x cannot read it again. 5.1 is installed and started, every zone, record set and DNSSEC key is compared with what was saved, and the server must answer SOA queries on port 53. Any failed step puts the 4.8 packages and the copied database back.
  - **What people notice:** the DNS server does not answer for about a minute; resolvers keep answering from their caches, and sites and email are not affected. DNSSEC keys stay the same, so DS records at registrars stay valid. Secondary name servers fetch the catalog zone once more, because PowerDNS 5 recounts it.
  - **Undo:** for 7 days, **Go back to old version** puts 4.8 and the database copied before the upgrade back, and the panel writes every zone again so changes made after the upgrade stay. **Remove old version** deletes the kept copies earlier; after 7 days they go on their own.
  - Later 5.1.x releases show as updates on the same page.
- **Rspamd 4** (4.2.3 today; was 3.8.1, which Rspamd no longer updates):
  - **New mail servers** get Rspamd from Rspamd's own archive (`rspamd.com/apt-stable`), with its signing key checked and the `rspamd` packages pinned to major version 4. If the archive cannot be reached during setup, Ubuntu's 3.8.1 is installed and the upgrade below is offered.
  - **Existing servers are not changed on their own.** Software → Other components now lists Rspamd; **Upgrade version** adds the archive, keeps the 3.8 package and a copy of `/etc/rspamd`, and installs the new version with the configuration files left as they are. `rspamadm configtest` must accept the configuration and Rspamd's milter must answer within a minute, or 3.8 and its settings are put back.
  - **What people notice:** for about a minute mail is passed on without spam checks or DKIM signatures; no mail is lost. DKIM keys and spam settings stay. The new version brings its own rules and scores, so look over spam folders in the first days.
  - **Undo:** for 7 days, **Go back to old version** puts 3.8 and its settings back while keeping what Serfex wrote since the upgrade (DKIM and spam settings in `local.d` and `override.d`). **Remove old version** deletes the kept copies earlier.
- **OWASP CRS 4.25.0** for ModSecurity (was Ubuntu's CRS 3.3.5, which Ubuntu 24.04 never updates):
  - **New installs** download CRS 4.25.0 from the project's GitHub release, check it against its SHA-256 and unpack it under `/opt/serfex/crs`. If the download fails, Ubuntu's 3.3.5 is installed and the upgrade below is offered.
  - **Why 4.25.0 and not 4.25.2:** 4.25 is CRS's long-term release line, but 4.25.1 and newer need libmodsecurity 3.0.16 and do not load in Ubuntu 24.04's 3.0.12 (rule 901181). Moving to 4.25.2 together with the newer engine is left for a later release.
  - **Existing servers are not changed on their own.** Software → Other components → ModSecurity → **Upgrade version**: Nginx must accept the new rules and a plain request must still get through, or the previous rules come back. The mode, paranoia level and site exceptions stay. CRS 4 settings use `blocking_paranoia_level`, and its early blocking rules count as blocked WAF events.
  - **What people notice:** no downtime; Nginx reloads. CRS 4 judges some requests differently, so on sites in **Block** mode look over the WAF events under Security in the first days and add an exception where a rule blocks legitimate requests.
  - **Undo:** for 7 days, **Go back to old version** returns to the previous rules; after that Ubuntu's rules package is removed. **Remove old version** does it earlier.
- **phpMyAdmin 5.2.3 and Adminer 6.3.0** (were Ubuntu's phpMyAdmin 5.2.1, which has two XSS issues fixed in 5.2.2, and Adminer 4.8.1):
  - They come from their makers' releases, checked against a SHA-256 pinned in Serfex, under `/opt/serfex/phpmyadmin` and `/opt/serfex/adminer`; phpMyAdmin's `setup` and `examples` folders are left out.
  - **New servers** get them with the database server. The new release must answer through Serfex's web server (phpMyAdmin must send to Serfex's sign-in, Adminer must show Serfex's sign-in page); if it cannot be downloaded or does not answer, Ubuntu's package is installed and the upgrade below is offered.
  - **Existing servers are not changed on their own.** Software → Database servers now lists phpMyAdmin and Adminer under "Web database manager"; **Upgrade version** moves each to its release with the same check, or Serfex's web server goes back to the one before. Databases → Database servers shows the versions in use and links to the upgrade.
  - **What people notice:** Serfex's web server restarts, so the panel may not answer for a second or two; sites and databases are not affected. Opening a database in phpMyAdmin or Adminer from the panel works as before.
  - **Undo:** for 7 days, **Go back to old version** serves Ubuntu's package again; after that it is removed. **Remove old version** removes it earlier.
