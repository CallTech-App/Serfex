MySQL and MariaDB are now tuned to the server's hardware and real usage: Serfex measures, suggests, watches the change it applied and rolls it back by itself if something goes wrong.

- **Measuring:** the running MySQL/MariaDB server is measured every hour (RAM, CPU, disk type, server counters, memory use of PHP-FPM and other services, the most time-consuming queries). Measurements are kept for 8 days; suggestions are based on the last 7 days of data.
- **Suggestions (Services → MySQL → Suggestions):** for the InnoDB buffer pool, temporary table size, maximum connections, the open table cache, disk I/O capacity and the slow query log, what is suggested and why is shown together with the measurement. Settings that are already right are listed with their reasoning too. The rules work while Serfex AI is off; when Serfex AI is on, it adds explanations to the suggestions and the slow queries.
- **Memory budget:** no suggestion may go over the set share of the server's memory (80% by default); PHP-FPM's peak usage over the last 7 days is taken into account. A suggestion that does not fit cannot be applied, and the reason is shown.
- **Applying and watching:** the change is applied without a restart and watched for 30 minutes; if the service stops, swap grows by more than 256 MB or free memory drops below 3%, the old value comes back by itself and a notification is sent. Every applied change can be reverted with Undo for 7 days. Settings changed by hand are locked, and the optimizer does not touch them.
- **Level and maintenance window (Services → Optimization):** Off, Suggestions only (default) or Apply in the maintenance window (03:00–05:00 by default). The same tab shows the server's memory budget and how it would change with the suggestions.
- **Slow queries:** the 5 most time-consuming queries (normalized, with values hidden) are shown with the site they belong to. Customers see their own sites' slow queries in site → Databases. Serfex never touches the schema itself; it only makes suggestions.
