Security update: two findings that were still open from the security scan were closed.

- **Forged email:** a customer's site (for example through PHP's `mail()` function) could send email with another customer's domain. Because the email left from this server, it passed SPF and was signed with DKIM too. Now every site's user can send only with its own domains. These are the site's name, its aliases, subdomains, redirected domains and the mail domain. The list is updated when the site changes and every hour.
- **Behaviour change:** applications that connect to port 25 from inside the server itself without authentication can no longer send with a domain hosted on this server. Postfix cannot tell which site such a connection comes from. These applications should use `sendmail` (PHP `mail()`, Laravel `MAIL_MAILER=sendmail`) or port 587 with a mailbox login. Webmail and the panel already use these paths; root and the panel's own email are not affected.
- **Deployment webhook:** GitHub and Bitbucket webhook signatures and the GitLab secret token are now verified; a request with a wrong signature is refused. Pull request events open a preview environment only when they are signed. This way someone who learns the address cannot open a preview with a fake pull request event. A secret is now added automatically to webhooks the panel adds through the Git account. For webhooks added by hand or before 0.1.49, enter the key at the end of the address in the secret field. Push deployments keep working without a signature.
- On servers with the mail server installed, the update rewrites the Postfix configuration; the mail settings do not need to be saved again.
