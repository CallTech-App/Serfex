The SSH terminal is no longer "Soon": the site's shell opens right in the panel, in the browser.

- **Where:** Site → Web server and development → **SSH terminal** (`/sites/{id}/terminal`). The SSH access page has a button for it too.
- **Who, and as which user:** only full administrators can open it. The shell starts as the site's own Linux user, in the site's folder; it never runs as root or through sshd. If the site's SSH access is not "SFTP and shell", or the customer is suspended, the terminal does not open; when shell access is turned off, open terminals close too.
- **Copy / paste:** selected text is copied automatically (this can be turned off). Ctrl+C copies when there is a selection and stops the running command when there is none. Paste with Ctrl+V, Ctrl+Shift+V, Shift+Insert, Cmd+V or the right-click menu. If the browser does not allow reading the clipboard (or on a phone), a paste box opens. Before pasting more than one line into a program other than the shell (for example `cat` or `mysql`), you are asked first.
- **Time and limits:** the session closes after 15 minutes without a key press (with a warning 1 minute before) or when 2 hours are up. At most 5 terminals can be open on the server at once; the same user's open sessions are listed on the page and can be closed.
- **Security:** for every session the panel issues a one-time ticket, valid for 60 seconds and tied to the address that opened it; the connection goes through the panel's own port (`:8443`), and no other port is opened. Opening and closing (with duration and reason) are written to the activity log; what is typed is not recorded.
- **Phone:** there is a key row for Esc, Tab, Ctrl, the arrow keys and Paste.
- **Installed servers:** the update rewrites the panel's web server configuration (`/terminal/socket`); you do not need to do anything else. If the Serfex agent restarts (for example during an update), open terminals close.
