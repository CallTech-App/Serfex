- **pgvector on PostgreSQL.** The customers' PostgreSQL server is now installed together with the package of the `pgvector` extension (`postgresql-<version>-pgvector`). Vector columns, HNSW/IVFFlat indexes and similarity search (AI embeddings, semantic search, Laravel's `vector` columns) can be used.
- A new **Extensions** card: Databases → PostgreSQL database. **Turn on** enables pgvector in that database. pgvector is not a "trusted" extension, so only a superuser can run `CREATE EXTENSION vector`. Serfex does that step, and then the database's users use vector columns with their own privileges. Laravel's `Schema::ensureVectorExtensionExists()` call passes without trouble while the extension is on. Customers can turn it on and off in their own databases. Turning it on and off can be reverted with **Undo**.
- **Turn off** removes the extension only when no column or index uses it. Nothing is deleted along with it (no CASCADE).
- Installed servers get the package at PostgreSQL's next **Update**/repair or when the extension is first turned on. If the package cannot be installed, the server keeps working and it is retried when the extension is turned on. Updates bring new pgvector releases too. On a version upgrade (for example 16 → 18) the new version's pgvector package is installed beforehand, so databases that use the extension do not block the upgrade.
