The server's SSH port can now be changed from the panel: Security → Sign-in security → SSH → Port → Change.

- **Two steps, so nobody is locked out:** SSH first opens on the new port while the old one stays open. A notice at the top of the Security page shows the command to try (`ssh -p 2222 root@…`). After logging in through the new port, "Connected, close port 22" closes the old one; "Cancel, stay on port 22" drops the change. Both ports stay open until one of the two is chosen, with no deadline, and open SSH sessions are never cut. Closing the old port has Undo.
- **Checked before it counts:** the agent refuses a port another program listens on, checks the new configuration with `sshd -t`, restarts SSH (on Ubuntu 24.04 through `ssh.socket`) and waits until SSH answers on every port. When it does not, the previous configuration is put back and SSH is restarted with it.
- **Everything follows the port:** Serfex's firewall opens the new port and closes the old one, Fail2ban's `sshd` jail watches the new port, `ufw` gets the new port too when it is on, and the SFTP/SSH connection details on site pages show the new port. `Port` lines in `/etc/ssh/sshd_config` and other `sshd_config.d` files are turned into comments, since sshd would otherwise listen on those ports as well.
- **Allowed ports:** 22, or 1024–65535 when free; the panel's port and the ports of web, mail, DNS, database and cache services are refused.
- A firewall in front of the server (the hosting provider's panel) is not changed; the dialog says to open the new port there too. The browser SSH terminal does not use the SSH port and keeps working.
