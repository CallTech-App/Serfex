- **Laravel queue workers fixed.** When writing the worker to the server, the panel sent the name of its own database connection (`pgsql`) instead of the worker's queue connection. The worker started with `queue:work pgsql` and crashed every few seconds with "The [pgsql] queue connection has not been configured." Now the worker runs with the selected connection or, when that is empty, with `QUEUE_CONNECTION` from the `.env` file. The update rewrites the workers of existing applications automatically; you do not need to do anything.
- The field in the worker settings is now called **Queue connection**, and its suggestions come from the application's own `config/queue.php`. A connection the application does not have (for example the name of a database connection) is not saved, and the reason is shown under the field.
- The Queues page shows a worker trying to run with an undefined connection with a red **No connection** status and an explanation; **Use the default connection** fixes it in one click and can be undone.
