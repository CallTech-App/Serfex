- New: Git deployment for non-Laravel sites (Sites → site → Git deployment). The repository is connected over https (public or with an access token) or over SSH; for SSH, Servik generates a deploy key for the site. You choose the branch and the target folder (`main` and `public_html` by default).
- "Deploy" writes the latest state of the branch into the folder; files deleted from the repository are removed, and files that are not in the repository (uploads, configuration files) stay as they are. No `.git` directory is placed in the folder.
- Optional automatic deployment: the webhook address works with GitHub, GitLab and Bitbucket pushes, or with an empty POST from CI.
- Post-deploy commands (for example `composer install --no-dev`) run as the site's user with the site's PHP version, never as root.
- Every deployment's history and log are kept; "Return to this release" goes back to an earlier commit. The first deployment keeps the files it overwrote and can be undone.
