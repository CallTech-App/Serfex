Databases now show up when moving from Plesk, and a section that cannot be read no longer silently turns into "0".

- **Plesk move:** in Plesk 18 the database servers table was renamed `DatabaseServers`; because the move asked for the old name (`db_servers`), the database list failed and the "What the subscription holds" screen showed "0 databases". Now the new name is tried first, then the old one; if neither can be read, databases are looked for directly on the server.
- **The database the site uses:** the database in Laravel's `.env` (`DB_DATABASE`, `DB_HOST`) and WordPress's `wp-config.php` is read too. A database on the same server that Plesk does not show as belonging to this subscription (registered under another subscription or created outside Plesk) is added to the move and reported in the "Note" list. A database named in a configuration file but missing on the server shows up as a warning too. For plain PHP or HTML sites Plesk's own record is used as before; files inside `vendor/` and `node_modules/` are not counted.
- **Certificates:** when Plesk keeps the certificate's key encrypted in its table, the certificate is read from its file under `/usr/local/psa/var/certificates/`.
- **Visible errors:** when a section (databases, mail, certificates…) cannot be read from Plesk, the error no longer stays only in the log; it appears in the "Note" list as "Could not be read from Plesk, this section may look incomplete: …".
