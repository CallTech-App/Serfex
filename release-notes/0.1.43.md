- **A name no longer lands on another customer's site.** Until now the Nginx that serves customer sites had no default server. An HTTPS request for a site that had no certificate yet (for example with Cloudflare in "Full" mode), a name not defined on this server, or the bare IP address went to the first site Nginx read. A visitor of one site saw another customer's site (or its error page). Serfex now writes its own default server (`/etc/nginx/sites-available/serfex-default.conf`). Every unmatched request on ports 80 and 443 gets a 404 with a "There is no site at this address" page. HTTPS uses a self-signed certificate, and the requested name is shown on the page. The page is in English by default and in Turkish with `#tr`.
- Ubuntu's own default site (`sites-enabled/default`, "Welcome to nginx!") is taken off the list of enabled sites. Its file stays in `sites-available`. If the administrator pointed that link at another file, it is left alone.
- The default server is written automatically with the update. There is no need to wait for a site change. If it cannot be written, the update still completes and the problem is shown at the next site change.
- **Certificates are now issued for domains behind Cloudflare too.** Before requesting a certificate, the panel checks whether the name points at this server. When it saw Cloudflare's proxy addresses it said "DNS does not point here yet" and did not get a certificate. Now a name that resolves only to Cloudflare addresses counts as pointing at this server. Let's Encrypt's validation comes through Cloudflare, and the default server answers over HTTPS too. Once the certificate is there, Cloudflare's safest mode, "Full (strict)", works as well. If the name goes to another server, validation fails and is retried every hour like other errors.
