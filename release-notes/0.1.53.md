A single unreadable file no longer brings down a site's backup.

- **Backups:** for security, a site's files are archived as the site's own user. A file this user could not read (for example a copy left owned by root by `sudo cp .env .env.bak`) used to fail the site's whole file backup with "tar failed: … Permission denied". Now that file is skipped, the rest of the site is backed up, and the backup details show as a warning which files were not included and what to do: "A file the roifex user cannot read was not backed up; make roifex its owner or delete it: ./laravel/releases/1/.env.bak-2026-10-29".
- Once the file's owner is fixed, the next backup (even an incremental one) picks it up. The same rule applies to the account's other files and to mailboxes.
- If the site folder itself cannot be read, the backup fails as before; only files inside it can be skipped.
