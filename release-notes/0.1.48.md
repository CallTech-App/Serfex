Security update. Vulnerabilities found in a security scan were fixed; updating every server is recommended.

- **Laravel pages:** a customer or team member with access to one Laravel application could see another application's log (`laravel.log`), deployment and command output, and deployment webhook address by changing the application number in the browser. The page is now locked to the application it was opened for, and permission is checked again on every render.
- **Usage report:** a customer could open another customer's usage report. Now they see only their own.
- **Read-only administrators:** with a request header added by hand, "Sign in as customer" could be used, which allowed changes on the customer's behalf. This is closed.
- **Web server directives** are now open to full administrators only. Because Nginx and Apache process these lines as root, administrators with the "Support" role could gain root on the server this way.
- Small leaks on the Backups and DNS pages that could show the names of sites, backups and zones belonging to other accounts were closed.
- Images in Serfex AI answers are no longer loaded; only their alt text is shown. This way an instruction hidden in logs cannot send data from the administrator's browser to an outside address.
- The agent and the command line are built with the current Go 1.27.3 (earlier releases were built with Go 1.24.0). `golang.org/x/crypto` was updated to v0.58.0 and `symfony/mime` to v7.4.22 (CVE-2026-45070).
- Releases no longer go out while a known vulnerability is present: the release workflow runs `govulncheck` and `composer audit`.
