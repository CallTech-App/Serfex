- The customer's disk limit is now really enforced: the file system's user quotas (ext4) are turned on, and every account can write files up to whatever is left of the plan's disk after mail, databases and Laravel backups. The limits are recalculated every 5 minutes.
- When the disk is full, uploads through the file manager or SFTP and file writes by sites are refused with a "Disk quota full" error; incoming email is deferred with `452 4.2.2 Mailbox full` (sending servers keep retrying for days, so no mail is lost). Mailboxes can still be opened, and once space is freed everything recovers within 5 minutes.
- The customer page, the customer's Usage page and the problem list on Overview show the customer whose disk is full; the customer list has a "Disk full" label. The 85% and 100% emails to the customer say clearly what will happen.
- An administrator can give a customer a disk limit different from their plan, or make it unlimited (Customer → Details and plan → Disk limit).
- A new "Disk quota" row in Settings → Server: status, "Turn on disk quotas", "Warn only" and, on servers where quotas cannot be turned on, the reason (btrfs/ZFS, XFS without uquota, a kernel without the quota module, a disk with no fstab line). In those cases the limit stays a warning as before.
- New installs turn quotas on automatically. On existing servers, "Turn on disk quotas" has to be clicked once in Server settings: the `quota` package (and `linux-modules-extra` if needed) is installed, quota options are added to `/etc/fstab` (the old version is kept as `/etc/fstab.before-serfex-quota`), and the disk is remounted without a reboot. If a step fails, the previous steps are rolled back.
