A site whose system account is missing on the server can now be deleted.

- **Deleting a site without an account:** a move left halfway, or a deletion cut off after the account was deleted, could leave a site without a system account. In that case the backup taken before deletion failed with "no archive could be taken: account …: user not found", and the site could not be deleted. Now, since there are no files to read, the backup skips only the files; databases, email, DNS and certificates are still backed up and the deletion goes on. The backup details say "Files: the system account (…) does not exist on the server". The same situation in scheduled site backups is now a warning, not an error.
- **The delete dialog says so beforehand:** if the account is missing on the server, the delete dialog shows this right at the start and says the files will not be in the backup. The notification shown when the deletion finishes also says the files were not backed up.
- **The panel record is cleaned up too:** when "Also delete the system user" is selected and the account is already missing on the server, the account record in the panel is deleted too (an empty record used to remain).
