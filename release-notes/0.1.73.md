Upgrading Adminer to 6.3.0 under Software no longer fails with "Adminer answers HTTP 500 without Serfex's sign-in page", and the Sites list shows what each site takes on disk and the total of the sites listed.

- **Adminer 6.3.0 upgrade:** Adminer's release file (`adminer-6.3.0.php`) is compiled without PHP type declarations, but Serfex's sign-in page for Adminer declared `permanentLogin(bool $create = false)`. PHP refused that override ("Declaration of SerfexAdminer::permanentLogin(bool $create = false): string must be compatible with Adminer\Adminer::permanentLogin($create = false)"), so every Adminer page answered HTTP 500. The upgrade check caught it and went back to the Adminer served before, so nothing broke, but the upgrade could not be done. The override now takes an untyped parameter, which fits both the release file and Adminer's sources.
- **What to do:** after updating Serfex, open Software, Database servers, "Web database manager" and press "Upgrade version" for Adminer again. Nothing changes on its own: a server keeps the Adminer it serves until an administrator presses the button.
- Checked against the real `adminer-6.3.0.php` (SHA-256 as pinned) with PHP-FPM settings like Serfex's and a PostgreSQL server: the check page, the one-time sign-in link, browsing a table and refusing a used link all work, with nothing in the PHP error log. The test of Serfex's Adminer sign-in page now also runs against a stand-in with the release file's untyped signatures.
- **Disk use on the Sites page:** a new Disk column shows what each site takes, the same total as its Disk usage page (web files, mail, databases and application backups, measured every 30 minutes) and links to that page. Below the list, "Total disk" adds up all the sites listed, on every page of the list; while searching, only the sites that match. A site not measured yet shows a dash. Customers see their own sites and their total.
