- New **WordPress toolkit**: Site → Applications → **WordPress**. One WordPress is managed per site; the work is done with WP-CLI as the site's own user.
- **Install WordPress**: one-click install when the site's web root is empty (only the "site is ready" page). A new MySQL/MariaDB database (`<prefix>wp`), the site name, the administrator account and the language (Turkish or English) are prepared together. The administrator password is shown once and not stored; `admin` and `administrator` are not accepted as user names. If the installation fails, the files and the database are rolled back. WordPress's address becomes the site's preferred name (with or without www). It is not offered on a site that has a Laravel application.
- If the site already has a WordPress (in the web root or up to two levels of subfolders), it is found; **Manage** brings it under management without touching its files.
- **Updates**: WordPress itself, a single plugin/theme, or **Update all**. A restore point is taken first from the database and the files to be updated; if the site errors after the update, the update is rolled back automatically. The last update can be taken back to its pre-update state with **Undo** from **History** within 7 days. The panel checks managed WordPress sites for updates every day (it does not update them automatically).
- **Sign in to WordPress**: the dashboard opens as the first administrator without a password, through a one-time link valid for two minutes; it is written to the activity log.
- **Maintenance mode**, activating/deactivating plugins, switching themes and WordPress's automatic update setting (default: security and maintenance releases only) change instantly and can be undone.
- **Security** tab: turn off the file editor, protect `wp-config.php`, no PHP execution in the uploads folder, hide sensitive files (these four are recommended and applied at install) and turn off XML-RPC. The rules live in the site's own Nginx includes.
- **Stop managing** leaves WordPress, its files and its database in place; it only removes Serfex's sign-in plugin, the web server rules and the restore points.
- Customers can manage the WordPress on their own sites the same way.
