The panel, the sign-in page and webmail are no longer listed in Google or other search engines in any way.

- **Panel and sign-in page:** every response from the panel (`:8443`) goes out with the `X-Robots-Tag: noindex, nofollow, noarchive, nosnippet` header, including the sign-in, setup, password reset, error and maintenance pages. Every page also has `<meta name="robots" content="noindex, nofollow">`. The header is sent both by Serfex's own web server and from inside the panel, so it applies even when the panel is reached another way.
- **Pages already listed drop out:** panel pages Google listed before (for example `https://yourdomain:8443/forgot-password`) see the `noindex` header on the next crawl and leave the results. That is why `robots.txt` deliberately does not block bots: Google cannot crawl a blocked page, so it cannot see `noindex` and the page stays in the results. To remove them right away, use Search Console → Removals.
- **phpMyAdmin and Adminer:** the same header was added to the pages of the database tools.
- **Webmail (SnappyMail / Roundcube):** the mail server's address and the webmail sign-in page get the same header.
- **Default site:** the "No site at this address" page shown for requests that reach the server but match no site gets the `noindex` header; customer sites' own robots.txt files are not touched.
- **Installed servers:** the update rewrites the Nginx configuration of the panel and webmail; you do not need to do anything else.
