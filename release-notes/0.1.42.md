- New **Copy site**: Site → Files and data → **Copy site**. The site is copied to a separate address (`staging.<domain>` by default) with the same system user, PHP version and web server. All files are copied (except logs); the address and database names in `wp-config.php`, `.env` and PHP configuration files are corrected for the copy, symbolic links that point into the site are pointed at the copy, and Laravel's cached configuration is deleted.
- Optionally, every database is copied to a new database named `<name>_copy`; the same database users reach it with the same privileges. Addresses in WordPress's database (serialized data included) are also changed to the new address, and the WordPress in the copy is managed too.
- **Hide from search engines** is on by default: `X-Robots-Tag: noindex` is added to every response, and "Discourage search engines" is turned on in WordPress.
- **Refresh from source** writes the live site's files and/or databases to the copy again. **Publish to the live site** writes the copy to the live site: a backup of the live site is taken first, if publishing fails the live site is restored immediately, and if you change your mind later you can go back with **Undo** within 7 days. Publishing is not offered on sites with a Laravel application (Git deployment and preview environments are used there).
- Email, scheduled tasks, FTP accounts and queue workers are not copied. If the domain's DNS is on the server, a record is added for the copy; the copy counts against the plan's site and database limits. Customers can copy their own sites.
- New **Cache and speed**: Site → Development → **Cache and speed**. **Page cache** (Nginx keeps the page PHP produced for between 1 minute and 1 day; 10 minutes by default), **browser cache** (1–365 days for images, CSS, JavaScript, fonts and video; 30 by default) and **gzip compression**. All start off. Signed-in visitors, responses that set cookies or are "private", and sign-in, admin, cart, checkout and API pages are never stored; extra paths can be excluded. There is a **Clear cache** button and an `X-Serfex-Cache` (HIT/MISS/BYPASS) response header. Changes can be undone.
- New **Composer** and **Node.js**: Site → Development. On non-Laravel sites too, Composer and npm/pnpm/Yarn/Bun commands run as the site's user, in the chosen folder, with live output. Folders with `composer.json` and `package.json` are listed; common commands and `package.json` scripts are one click away. A site can choose the Node.js version its commands (and Laravel builds) use. Customers need the plan's "Command and Tinker access" feature.
