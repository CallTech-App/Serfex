Email from sites is now sent only by signing in with a mailbox.

- **Sending without sign-in is closed:** sites cannot send with `sendmail` (PHP `mail()`), and email sent over SMTP from the server itself without signing in is not delivered anywhere. This is exactly how spam from a hacked site goes out and gets the server's address onto blocklists. Sending happens with a mailbox, like any email client: server = the mail server's name, port 587 (STARTTLS), user name = the mailbox's address. A mailbox can send only with its own address. root, the panel's own email and webmail are not affected.
- **"Connect a mailbox" in Laravel:** when the application's settings cannot send from this server (Laravel's default is `MAIL_MAILER=log` and `hello@example.com`), the Environment (.env) section says why. **Connect a mailbox** takes one of the site's mailboxes and its password and writes the SMTP settings to the `.env` file (with Undo; the old version stays in the history). If there is no mailbox, it links to creating one. The email row on the overview shows the problem too. An application that uses its own SMTP server or a service such as SES or Postmark is left alone.
- **WordPress:** since WordPress uses PHP `mail()` by default, an SMTP plugin (WP Mail SMTP, FluentSMTP…) is needed. If there is none, the WordPress page says so and shows the settings to enter.
- **A clear error message in the log:** refused sends in the Laravel log now say what they mean: sendmail is off, no sign-in, wrong password, or the sender address does not belong to the mailbox. Below it is a link to the email setting.
- **`.env` edited by hand:** when `sed -i` or an editor turned the `current/.env` link into a regular file, the change was lost at the next deployment. Serfex now takes this file back as `shared/.env` before a deployment and before a save in the panel; the old one is kept as `shared/.env.old`.

**Before updating:** applications that use `MAIL_MAILER=sendmail` or `127.0.0.1:25` without sign-in, and WordPress sites without an SMTP plugin, cannot send email after the update. Create a mailbox for each (for example `noreply@yourdomain.com`) and enter that mailbox's SMTP details in the application; in Laravel, **Connect a mailbox** does this for you.
