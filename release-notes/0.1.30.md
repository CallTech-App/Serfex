- Database servers can now be **upgraded to a new major version** (Software → Database servers → **Upgrade version**). Only versions Serfex allows are offered: PostgreSQL to the newest version (18 at the moment), MySQL and MariaDB one LTS ahead at a time (MySQL 8.4 → 9.7, MariaDB 11.8 → 12.3). New versions are never installed automatically.
- The upgrade is shown step by step in a progress dialog: a free disk check (data × 2 + margin), maintenance mode, a full dump of every database with its row counts, the new version, data migration, then a comparison of every database, user and table row count. If a step fails, the old version comes back; no data is lost.
- PostgreSQL brings up the new cluster by copying it next to the old one (`pg_upgradecluster`, copy mode); the old cluster stays, stopped. For MySQL and MariaDB a cold copy of the data folder and the old packages are kept; on rollback both are put back.
- The old version is kept for 7 days and then deleted automatically; **Remove old version** deletes it sooner. The pre-upgrade dump stays under `/var/lib/serfex/backups/databases` for 30 days. The panel's own PostgreSQL (5433) is not affected at all.
- While the upgrade runs, customers see a maintenance notice on database pages, and database and user operations on that server are refused with a clear message. The upgrade runs in the backup queue and cannot start while a backup or restore is running.
