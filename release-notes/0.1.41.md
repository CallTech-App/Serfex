- **Picking the repository from a list (GitHub, GitLab, Bitbucket):** in Git deployment, Laravel installation and Laravel → Deployments, the repository is now searched for and picked from your connected account's list, and the branch comes from a list too. Serfex adds the read-only deploy key and the deployment webhook to the repository itself (push and pull request events for Laravel); when the repository connection is removed or the Laravel application is deleted, it removes both from the repository itself as well. Code is always pulled with the site's deploy key, never with the account's access grant. If the provider refuses the key (when you are not an admin of the repository), the key is shown to be added by hand as before. Typing the address by hand is still possible.
- **Settings → Git providers:** an OAuth application is set up for each provider (GitHub OAuth App, GitLab application, for GitLab.com or your own server, and Bitbucket OAuth consumer). The page shows the callback address to enter at the provider and the steps; the secret is stored encrypted. When none is turned on, everything works as before.
- **Account → Git accounts:** every user (administrator, customer, Laravel team) connects or disconnects their own GitHub, GitLab or Bitbucket account. Access grants are stored encrypted; GitLab and Bitbucket grants are renewed before they expire.
