- **SSH access** was added to sites (site → Development → SSH access). The site's own system user can connect with an SSH key or, optionally, a password. Off by default.
- **SFTP only**: the user is locked to their home folder (`/home/<user>`); they cannot see the rest of the server, run commands or open tunnels. Uploaded files become the site's own files (644/755).
- **SFTP and shell**: only an administrator can turn it on. The user can run commands with bash in their home folder (Composer, Git, Artisan) and open an SSH tunnel to the database.
- Keys are kept in the panel (ED25519, ECDSA, RSA of at least 2048 bits); the server accepts only the keys in the panel. The password is shown once and not stored; password sign-in can be turned off. Access changes, key deletion and turning off the password can be undone.
- Plans got an **SSH access** feature: on in Professional, Laravel Pro and Business, off in Starter. A suspended customer's user cannot connect; once the suspension is lifted, keys and password work again. Failed sign-ins are blocked by the existing Fail2ban sshd rule.
