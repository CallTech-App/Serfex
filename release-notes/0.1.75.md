Webmail sign-ins are now protected against password guessing, and every mail domain can get its own webmail address (https://webmail.<domain>/).

Webmail (Roundcube or SnappyMail) has always had its own sign-in page at the mail server's address (for example https://mail.example.com/), where a mailbox user signs in with the mailbox address and password without the panel; the panel's one-click "Webmail" link works as before. Webmail signs in to the mail server from the server itself, so the existing Fail2ban mail jails never saw the visitor's address and the sign-in form could be tried without limit.

- **New Fail2ban jail "Webmail sign-in" (serfex-webmail):** ten failed webmail sign-ins from one address within 10 minutes close the web ports (80/443) to that address for an hour. Bans show up under Security with the other Fail2ban bans and can be lifted there. Addresses banned repeatedly fall under the existing one-week repeat-offender jail.
- Roundcube logs failed sign-ins (wrong password, or a mailbox locked by Roundcube's own limit of 3 failures a minute) to the journal with the visitor's address; an expired sign-in form or a mail server that is down is not counted. SnappyMail logs them through its built-in auth_syslog option.
- The address is logged before the user name typed into the form, so a crafted user name cannot get another address banned. This server's own addresses and Cloudflare's proxy addresses are never banned.
- Existing servers get this with the update: the webmail settings are rewritten (no reload, no new Roundcube or SnappyMail version) and, when Fail2ban is installed, the jail is added within a minute. Without Fail2ban (Software Management) nothing is banned.

**Webmail at each mail domain's own address.** Until now every mailbox user signed in at the one shared mail server address (for example https://mail.example.com/), so a customer could not give their users an address on their own domain.

- With the new E-mail settings option "Give every domain its own webmail address", each mail domain gets https://webmail.<domain>/. Users sign in there with the full mailbox address and password; the panel's one-click webmail link and the shared mail server address keep working.
- Serfex writes a webmail A record (and AAAA when the server has IPv6) to the domain's zone on this server, DNS-only on Cloudflare, like the other mail records. A record you changed by hand, for example one still pointing at an old Plesk or cPanel server, is left alone and shows as "Different" until "Write the recommended records" replaces it. When the domain's DNS is elsewhere, the mail DNS table shows the record to add.
- Each address gets its own Let's Encrypt certificate (HTTP validation), issued as soon as the name points here, retried every hour until then and renewed like the others. Until the certificate is in place, http://webmail.<domain> sends users to the shared address.
- The mail domain page shows the address above the mailbox list with a copy button and its state (Ready, Waiting for DNS, Getting the certificate), so customers see it too. The mail DNS table has a new "Webmail address" row and the e-mail client settings list the webmail address.
- New addresses are kept out of search engines (noindex) and covered by the "Webmail sign-in" Fail2ban jail above.
- **Existing servers:** the option stays off after the update, so nothing is written to your DNS zones on its own. E-mail settings shows a "New" box with an Open button that turns it on for every mail domain. New servers have it on. Turning it off removes the webmail records and web server blocks Serfex added, with Undo; certificates are kept but no longer renewed.
