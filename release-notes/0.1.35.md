- A new **Preferred address** setting (like "Preferred domain" in Plesk): should visitors go to `example.com` or `www.example.com`? The other name goes to the preferred one with a permanent (301) redirect; the path and query are kept, and the request never reaches the application. With "No redirects", both names open the site separately (the old behaviour).
- In the **Add site** dialog this choice replaces the "Also open with www." box: `example.com` (default), `www.example.com`, both open, or only `example.com` (no www. added).
- On existing sites the setting comes as **No redirects**, so nothing changes by itself. It can be changed from Site → Domains → **Domain aliases**, and the change can be reverted with Undo. The site tools also have a "Preferred address" row.
- The redirect starts only when the preferred name is on the certificate, so a visitor is never sent to an address that gives a certificate error. On a site without a certificate only the bare domain can be preferred; once the www. name is on the certificate, the redirect starts by itself.
- When a Laravel application is installed, `APP_URL` is now written with the preferred address. An application whose `APP_URL` has www and that has `trustHosts()` on gave "400 Bad Request" on the bare domain; choosing www as the preferred address solves it.
- API: `POST /api/v1/sites` takes `preferred_host` (`bare`, `www`, `none`) and shows it in the site response. Command line: `serfex sites create example.com --prefer www`.
- Site backups also store and restore the preferred address.
